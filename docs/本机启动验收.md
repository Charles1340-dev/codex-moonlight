# 0.2.25 本机启动验收

本次修复针对原生加载页缺少航海开场，以及重启后 Mini 没有连接增强路飞的问题。

## 已安装入口

桌面 `Codex.lnk` 与开始菜单 `Codex - GPT 龙娘.lnk` 均指向 `%LOCALAPPDATA%\MoonlightVoyage\0.2.25\MoonlightCodex.exe --dreamskin`。原有版本和快捷方式备份保留。

从这两个入口启动会复用已有 Codex；没有运行时才创建进程。航海动画在原生加载页内准备，窗口显示后计时，完成或按 Esc 后揭开同一窗口的工作区。

桌宠继续由「设置 → 迷你界面和智能伙伴 → 路飞 · 航海版 → 显示 Mini」控制。右键菜单只提供常态、四档蛇人和五档，每种形态六招。模型推理强度仍为六档。

## 验证证据

- `npm run build` 与 `npm test` 通过，共 22 项测试。
- 正式安装包的桌宠检查通过：三形态、18 个招式、单路视频播放、拖动边界、紧凑菜单、系统右键信号和点击外部关闭。
- `qa/cold-start-v25.json` 记录了主进程替换后的真实冷启动：`introSeen`、`introBeforeWorkspace`、`finished` 均为 `true`，前后浏览器身份不同。加载页发生重新加载后也重新接入了开场。
- 冷启动结束时 Mini 页面尚未建立；随后独立复查确认 Mini 当前隐藏、增强桌宠已准备好、原生浮层遮罩租约有效。该状态不应误报为桌宠连接失败。
- 本机安装的启动桥与源码一致；发行 ZIP 内的启动桥、航海接入代码及构建动画一致，SHA-256 校验通过。
- 公开 ZIP 不含 `local-themes` 私有角色素材；本机安装另行加载 v12 素材包。

冷启动报告中的首次采样时间包含原生程序自身初始化和连接验证，不能直接用作动画本身的时长，也不代表操作系统创建窗口前已经有可绘制页面。
